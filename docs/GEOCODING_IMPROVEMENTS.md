# ジオコーディング精度向上 - 実装説明

## 概要

Nominatim API を使用したジオコーディング機能の検索精度を大幅に向上させました。
これまで「新宿駅」などのキーワードで、関連性の低い地名や遠い地点が返される問題を解決しました。

## 問題の背景

### 発生していた現象

- 「新宿駅」を検索すると「川崎」など関連性の低い地点が返されることがあった
- 全国の検索結果が混在していため、ユーザーが目的地を見つけにくかった

### 根本原因

Nominatim API のデフォルト設定では：
1. **検索範囲の制限がない**：`countrycodes=jp` だけでは日本全国の結果が返される
2. **結果の優先順位付けが不完全**：地理的な近さを考慮していない
3. **座標の精度チェックがない**：日本国外の座標が混在する可能性がある

## 実装の改善内容

### 1. 検索パラメータの最適化

```typescript
// ビューボックスで関東圏を検索範囲として指定
// [西経度, 南緯度, 東経度, 北緯度]
url.searchParams.set("viewbox", "138.4,34.0,141.5,36.5");
url.searchParams.set("bounded", "1");
```

**設定値の意味：**
- **西経度 138.4°**：関東西部（山梨県境）
- **南緯度 34.0°**：関東南部（千葉県南部）
- **東経度 141.5°**：関東東部（千葉県沖）
- **北緯度 36.5°**：関東北部（栃木県北部）
- **bounded=1**：viewbox 外の結果を優先度を下げて処理

### 2. 候補の多数取得と精度フィルタリング

```typescript
// 候補数を 5 から 10 に増加
url.searchParams.set("limit", "10");

// 日本座標範囲のフィルタリング
const filtered = data
  .filter((d) => {
    const lat = parseFloat(d.lat);
    const lng = parseFloat(d.lon);
    return lat >= 30 && lat <= 46 && lng >= 130 && lng <= 146;
  })
```

**効果：**
- より多くの候補から最適なものを選別
- 座標範囲チェックで日本国外の誤検出を防止

### 3. 重要度スコアでのソート

```typescript
.sort((a, b) => b.importance - a.importance)
.slice(0, 5);
```

Nominatim が提供する `importance` スコア（0～1）を使用して、
より信頼性の高い結果を優先的に返却します。

### 4. User-Agent の設定

```typescript
headers: {
  "User-Agent": "SpotBase/1.0 (Broadcast location management system)",
}
```

Nominatim の利用ポリシーに準拠し、適切な User-Agent を指定。

## 使用上の注意

### viewbox の設定について

現在の `viewbox="138.4,34.0,141.5,36.5"` は関東圏を中心としています。
ユーザーが日本の他地域でも検索できるよう、以下の工夫をしています：

1. **bounded=1 の効果**：
   - viewbox 内の結果を優先するが、外の結果を完全に除外しない
   - 名古屋や大阪の駅も検索可能

2. **日本座標範囲フィルタリング**：
   - 日本全国（北緯 30～46°, 東経 130～146°）の座標を受け入れ
   - 日本国外のデータは確実に除外

## 今後の改善案

1. **複数の viewbox 設定**：
   - ユーザーの過去検索履歴から検索地域を推測
   - その地域を中心とした viewbox に動的に切り替え

2. **キーワード分析**：
   - 「駅」「空港」「港」などのキーワードを抽出
   - POI（Point of Interest）の種類に応じて検索パラメータを調整

3. **ローカル API の検討**：
   - 国土地理院のジオコーディング API との併用
   - より高精度な日本国内検索
